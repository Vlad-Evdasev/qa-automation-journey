# 🎯 Программа обучения: QA Automation Engineer (JavaScript / TypeScript)

> Персональная программа для **Влада**. Путь: **Manual QA → Automation QA (Junior)**.
> Стек: **TypeScript + Node.js + Playwright + Jest + API + CI/CD**.
> Темп: 5–10 ч/нед. Ориентир: ~9–12 месяцев. Привязка — к **прохождению блоков**, не к календарю.

---

## Как устроена программа

Программа разбита на **5 фаз** и **17 модулей**. Каждый модуль — это законченный блок со структурой:

- **🎯 Зачем** — как навык применяется в реальной работе автотестировщика.
- **📚 Теория** — что изучить и понять.
- **🛠 Практика** — конкретные задания, которые нужно сделать руками (это главное!).
- **🏆 Мини-проект** — закрепляющее задание, результат кладём в отдельную папку.
- **✅ Критерий готовности** — чек, по которому понимаем, что можно двигаться дальше.
- **📎 Ресурсы** — проверенные материалы (упор на русскоязычные + официальную документацию).

**Правило программы:** не переходим к следующему модулю, пока не выполнен мини-проект и не закрыт критерий готовности. Лучше медленно и руками, чем быстро и «прочитал».

**Отслеживание прогресса:** твой текущий статус живёт в [PROGRESS.md](PROGRESS.md). Я обновляю его после каждого занятия и **помню его между сессиями** — просто напиши мне «я закончил модуль N» или «давай продолжим», и я подхвачу с нужного места.

# 🟢 ФАЗА 0. Фундамент и инструменты

*Цель фазы: настроить рабочее место как у настоящего разработчика и начать думать как автоматизатор.*

### Модуль 1. Мышление автоматизатора + рабочая среда
**🎯 Зачем:** Прежде чем писать автотесты, нужно понимать *что* автоматизировать и иметь настроенные инструменты. Как manual QA половину теории ты уже знаешь — здесь мы переориентируем её на автоматизацию.
**⏱ Ориентир:** ~8–10 часов.

**📚 Теория:**
- Освежаем с новым фокусом: пирамида тестирования (unit → API/integration → e2e/UI) — **почему UI-тестов должно быть мало**, а unit много.
- Типы тестов глазами автоматизатора: что дёшево и стабильно автоматизировать, а что нет.
- Что такое «хороший кандидат на автоматизацию» (регресс, повторяемость, критичный путь) и что автоматизировать НЕ надо.
- Как устроена работа автоматизатора в команде: где живут тесты, что такое прогон, флаки-тест, отчёт.
- Инструменты: терминал (базовые команды), редактор кода VS Code, что такое Node.js и зачем он нам.

**🛠 Практика:**
1. Установи **Node.js (LTS версия)**, **VS Code**, проверь `node -v` и `npm -v` в терминале.
2. Настрой VS Code: расширения ESLint, Prettier, Playwright Test, GitLens.
3. Освой 15 базовых команд терминала: `cd`, `ls`, `mkdir`, `touch`, `rm`, `pwd`, `cat` и т.д.
4. Возьми любой знакомый сайт (например [saucedemo.com](https://www.saucedemo.com)) и **письменно распиши**, какие 5 сценариев ты бы автоматизировал в первую очередь и почему, а какие оставил бы на ручное.

**🏆 Мини-проект:** Документ `phase0-analysis.md` — твой разбор сайта: пирамида для этого приложения (что на каком уровне тестировать) + список приоритетов автоматизации с обоснованием.

**✅ Критерий готовности:**
- [ ] Node.js и VS Code установлены и работают.
- [ ] Могу объяснить, почему UI-тесты дорогие, а unit — дешёвые.
- [ ] Сделал разбор сайта.

**📎 Ресурсы:** [Пирамида тестирования (Martin Fowler)](https://martinfowler.com/articles/practical-test-pyramid.html) · [Node.js download](https://nodejs.org) · [VS Code](https://code.visualstudio.com)

### Модуль 2. Система контроля версий: Git и GitHub
**🎯 Зачем:** Весь код тестов хранится в Git. Без уверенного Git тебя не возьмут даже стажёром. Это ежедневный инструмент.

**📚 Теория:**

- Ветки: `branch`, `checkout`/`switch`, `merge`. Зачем нужны ветки в командной работе.
- Конфликты слияния и как их разрешать.

4. Запушь репозиторий на GitHub, создай Pull Request «сам себе», добавь описание.
5. Пройди интерактивный тренажёр [Learn Git Branching](https://learngitbranching.js.org/?locale=ru_RU) — минимум до раздела с merge.

**🏆 Мини-проект:** Публичный репозиторий на GitHub `qa-automation-journey` с README, где ты будешь хранить весь код обучения. Это **начало твоего портфолио** — работодатели смотрят GitHub.

# 🔵 ФАЗА 1. Программирование на JavaScript

*Цель фазы: научиться писать код. Это твой главный пробел как manual QA и 60% успеха в automation. Не спеши — фундамент решает всё.*

### Модуль 3. JavaScript: основы языка
**🎯 Зачем:** Автотест — это программа. Переменные, типы и операторы — «алфавит», на котором написан каждый тест.
**⏱ Ориентир:** ~15–18 часов.

**📚 Теория:**
- Как запускать JS: в браузере (консоль DevTools) и через Node.js (`node file.js`).
- Переменные: `let`, `const`, `var` (и почему `var` больше не используют).
- Типы данных: string, number, boolean, null, undefined, object, symbol, bigint.
- Операторы: арифметические, присваивания.
- **Сравнения: `==` vs `===`** — критично для тестов (assertions построены на сравнениях!).
- Логические операторы: `&&`, `||`, `!`, короткое замыкание.
- Приведение типов (type coercion) — почему `'5' + 1 = '51'`, а `'5' - 1 = 4`.

**🛠 Практика:**
1. Напиши 10 маленьких скриптов в Node.js, играя с типами и приведением.
2. Реши 15 задач на [learn.javascript.ru](https://learn.javascript.ru/) из разделов про типы и операторы.
3. Напиши функцию, которая принимает данные и возвращает «true/false, валиден ли email» (простая проверка через строки).
4. Реши 10 задач уровня 8 kyu на [Codewars](https://www.codewars.com).

**🏆 Мини-проект:** Скрипт `type-explorer.js`, который на входе получает разные значения и печатает их тип, результат `==` и `===` сравнения с другими значениями, и объясняет приведение. Закоммить в репозиторий.

**✅ Критерий готовности:**
- [ ] Точно понимаю разницу `==` и `===` и могу привести пример, где они дают разный результат.

### Модуль 6. Асинхронный JavaScript
**🎯 Зачем:** **Это сердце автоматизации.** Клик по кнопке, ожидание элемента, запрос к API — всё асинхронно. Playwright и API-тесты построены на `async/await`. Без этого модуля дальше идти нельзя.
**⏱ Ориентир:** ~18–20 часов.

**📚 Теория:**
- Синхронный vs асинхронный код — почему JS однопоточный, но не блокируется.
- **Event Loop** (цикл событий): call stack, callback queue, microtasks — на уровне понимания, без фанатизма.
- Колбэки и «callback hell».
- **Промисы (Promise):** `pending / fulfilled / rejected`, `.then`, `.catch`, `.finally`.
- `Promise.all`, `Promise.race` — зачем нужны.
- **`async / await`** — современный способ (то, что ты будешь писать 99% времени).
- Обработка ошибок в асинхронном коде: `try / catch`.

**🛠 Практика:**
1. Напиши функцию `delay(ms)`, возвращающую промис, который резолвится через заданное время.
2. Сделай цепочку: «получить пользователя → получить его посты → получить комментарии» через реальные запросы к jsonplaceholder (используй `fetch`, встроенный в Node 18+).
3. Перепиши эту цепочку с `.then` на `async/await`.
4. Оберни запрос в `try/catch`, специально сломай URL и обработай ошибку.
5. Через `Promise.all` запроси данные 5 пользователей параллельно и собери в один массив.

**🏆 Мини-проект:** `async-api-client.js` — маленький асинхронный клиент: функции `getUser(id)`, `getUserPosts(id)`, `getAllUsers()`, каждая с обработкой ошибок. Это прямая репетиция будущих API-тестов.

**✅ Критерий готовности:**
- [ ] Могу объяснить своими словами, что такое промис и зачем `await`.
- [ ] Написал рабочую цепочку асинхронных запросов.
- [ ] Понимаю, зачем `try/catch` вокруг `await`.

**📎 Ресурсы:** [learn.javascript.ru — Промисы, async/await](https://learn.javascript.ru/async) · [Event Loop визуализация](http://latentflip.com/loupe/)

### Модуль 8. TypeScript для тестировщиков

- Дженерики (generics) — базово (`Array<T>`, `Promise<T>`).

### Модуль 9. Node.js, npm и чистый код
**🎯 Зачем:** Управление зависимостями (npm) и единый стиль кода (ESLint/Prettier) — это гигиена, которую проверяют на code review в любой команде.
**⏱ Ориентир:** ~10–12 часов.

**📚 Теория:**
- Node.js инфраструктура: что такое runtime, глобальные объекты, модульная система (CommonJS vs ES Modules).
- Event loop в Node (связка с модулем 6).
- **npm:** `package.json`, `package-lock.json`, `dependencies` vs `devDependencies`, `npm install`, `npm scripts`.
- **npx** — запуск пакетов без установки.
- **ESLint** — статический анализ, ловля ошибок и антипаттернов.
- **Prettier** — автоформатирование.
- Принципы чистого кода: понятные имена, маленькие функции, DRY, без «магических чисел».

**🛠 Практика:**
1. Инициализируй проект `npm init`, разбери каждое поле `package.json`.

### Модуль 10. Unit-тестирование (Jest)
**🎯 Зачем:** Основа пирамиды. Здесь ты осваиваешь саму механику теста: подготовка → действие → проверка (Arrange-Act-Assert), которая одинакова на всех уровнях.
**⏱ Ориентир:** ~15–18 часов.

**📚 Теория:**
- Анатомия теста: `describe`, `it`/`test`, `expect`, matchers (`toBe`, `toEqual`, `toContain`, `toThrow`…).
- Паттерн **AAA (Arrange-Act-Assert)**.
- Хуки: `beforeEach`, `afterEach`, `beforeAll`, `afterAll`.
- Обзор экосистемы: **Jest** (наш выбор), Mocha, Jasmine — чем отличаются и почему Jest популярен.
- Моки и стабы (`jest.fn()`, `jest.mock`) — базово.
- Покрытие кода (coverage) — что это и как не превращать в самоцель.
- Хороший тест: изолированный, повторяемый, с понятным названием.

**🛠 Практика:**
1. Установи Jest, напиши тесты для функций из ранних модулей (валидация email, проверка пароля).
2. Отработай разные matchers на 20+ проверках.
3. Напиши тесты с `beforeEach` (общая подготовка данных).
4. Замокай функцию и проверь, что она была вызвана с нужными аргументами.
5. Специально напиши падающий тест и научись читать вывод ошибки.

**🏆 Мини-проект:** `unit-tests/` — покрой тестами свой модуль `test-report-analyzer` из Модуля 5: минимум 15 тестов, включая крайние случаи (пустой массив, некорректные данные).

### Модуль 12. UI-автоматизация: Playwright
**🎯 Зачем:** Вершина пирамиды и самый «продающий» навык. **Playwright** — самый современный инструмент (обгоняет Selenium/Cypress по возможностям): авто-ожидания, трейсы, кросс-браузерность из коробки.
**⏱ Ориентир:** ~25–30 часов (самый объёмный модуль).

**📚 Теория:**
- Что такое WebDriver и зачем он был нужен (контекст: Selenium — «дедушка», всё ещё в вакансиях).
- Почему Playwright: auto-waiting, изоляция контекстов, скорость, трейсинг.
- Установка `@playwright/test`, структура проекта, `playwright.config.ts`.
- **Локаторы:** `getByRole`, `getByText`, `getByLabel`, `getByTestId`, CSS/XPath — и почему user-facing локаторы лучше.
- Действия: `click`, `fill`, `type`, `check`, `selectOption`, `hover`, `press`.
- **Авто-ожидания и web-first assertions** (`expect(locator).toBeVisible()`) — почему больше не нужны `sleep`.
- Работа с несколькими элементами, фреймами, вкладками, диалогами.
- Скриншоты, видео, **trace viewer** — суперсила для отладки.
- Фикстуры Playwright, хуки, параметризация.
- Обзор для эрудиции: WebdriverIO, Cypress — чем отличаются от Playwright (на собеседовании спрашивают).

**🛠 Практика:**
1. Установи Playwright, запусти сгенерированный пример, открой отчёт и trace viewer.
2. Автоматизируй логин на [saucedemo.com](https://www.saucedemo.com): позитивный и негативные сценарии.
3. Отработай локаторы на [the-internet.herokuapp.com](https://the-internet.herokuapp.com): чекбоксы, дропдауны, динамические элементы, алерты.
4. Автоматизируй сценарий покупки: логин → добавить товар в корзину → checkout → проверка.
5. Используй `codegen` (`npx playwright codegen`) для записи, потом перепиши руками.
6. Специально сломай тест и найди причину через trace viewer.

**🏆 Мини-проект:** `ui-tests/` — 15+ UI-тестов на saucedemo, покрывающих логин, каталог, корзину и checkout. Пока без POM (его добавим в след. модуле) — сначала прочувствуй «сырые» тесты.

**✅ Критерий готовности:**

- [ ] Умею отлаживать через trace viewer.
- [ ] Могу объяснить, почему Playwright лучше «голого» Selenium.

**📎 Ресурсы:** [Playwright docs](https://playwright.dev/) · [Playwright: Getting Started](https://playwright.dev/docs/intro) · [saucedemo](https://www.saucedemo.com) · [the-internet](https://the-internet.herokuapp.com)

## 🔑 Принципы, которые сделают тебя сильным джуном

1. **Практика > теория.** Правило 20/80: 20% времени читаешь, 80% — пишешь код руками.
2. **Всё в Git.** Каждое задание коммить. GitHub — твоё резюме.
3. **Не заучивай — понимай.** Сможешь объяснить своими словами = знаешь.
4. **Ошибки — это данные.** Сломанный тест учит больше рабочего. Учись читать ошибки.
5. **Строй портфолио с первого дня.** К концу у тебя будет 3–4 репозитория, которые говорят за тебя.
6. **Спрашивай меня.** Застрял, не понял тему, нужен разбор или доп. задачи — пиши. Я здесь как твой ментор.
