# Разбор saucedemo.com для автоматизации

> Мини-проект Модуля 1. Автор: Влад.
> Сайт: https://www.saucedemo.com (тестовые аккаунты видны прямо на странице логина).

---

## 1. Что это за приложение

Интернет-магазин мерча Sauce Labs (рюкзаки, футболки, толстовки, фонарик для велосипеда и т.п.). Учебный сайт: реального бэкенда нет — все данные лежат прямо в браузере, поэтому это, по сути, чистый фронтенд.

Основные экраны:

- Экран логина (с заранее заданными тестовыми аккаунтами)
- Каталог товаров (список, сортировка)
- Карточка товара
- Корзина
- Оформление заказа (форма с ФИО и индексом → обзор → подтверждение)

---

## 2. Пирамида тестирования для этого приложения

**🟩 Unit (много, быстрые):** проверка отдельной логики

- расчёт итоговой суммы в корзине (сумма товаров + налог)
- форматирование цены (например, `$29.99`)
- валидация полей формы заказа (пустое имя / фамилия / индекс)

**🟨 API / интеграция (средне):**

- На saucedemo этого уровня практически нет — у сайта нет настоящего сервера, всё работает в браузере.
- В реальном магазине сюда попали бы: запрос авторизации (`POST /login`), добавление товара в корзину (`POST /cart`), получение списка товаров (`GET /products`) — проверка ответов сервера без открытия браузера.

**🔺 E2E / UI (мало, только критичное):**

- логин (позитивный и негативный — например, `locked_out_user`)
- добавление / удаление товара в корзину и проверка счётчика
- открытие карточки товара и просмотр информации
- полный сценарий заказа: логин → товар → корзина → оформление → подтверждение → возврат на главный экран

---

## 3. Топ-5 сценариев на автоматизацию (с обоснованием)

| #   | Сценарий                                          | Уровень пирамиды | Почему в приоритете                                                                              |
| --- | ------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------ |
| 1   | Полный заказ товара (логин → корзина → оформление → подтверждение) | UI (E2E)         | Главный бизнес-путь: ради него существует магазин. Если он сломан — продукт не работает.          |
| 2   | Логин (позитивный + негативный)                   | UI               | Без него невозможно пользоваться продуктом — ворота ко всему остальному функционалу.             |
| 3   | Добавление / удаление товара в корзину            | UI               | Основной функционал, без которого невозможно заказать товар.                                     |
| 4   | Валидация полей при заказе                        | Unit             | Человек может ошибиться при заказе — без валидации не будет возможности доставить товар.          |
| 5   | Расчёт суммы корзины                              | Unit             | Если сумма неверная, то при заказе мы либо получаем убытки, либо обманываем пользователя.         |

> Примечание: «открытие карточки товара» из первого черновика я убрал из топ-5 и заменил на полный E2E-заказ — он критичнее. Карточку тоже стоит покрыть, но приоритет ниже.

## 4. Что НЕ стоит автоматизировать (или низкий приоритет)

- Сортировка/фильтрация товаров, если названия часто меняются и непонятен ожидаемый результат — автотесту сложно определить, что считать правильным. *(Хотя сортировку по цене автоматизировать можно — результат там предсказуем.)*
- Корректное отображение картинок — картинки и товары постоянно меняются, это зона **визуального тестирования**, а не обычных автотестов. (На saucedemo это специально ломает аккаунт `problem_user`.)
